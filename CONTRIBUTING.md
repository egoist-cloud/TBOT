# Contributing

## Работа с git

### Сообщения коммитов

Формат — `<тип>: <что сделано>` (Conventional Commits), описание по-русски.
Типы, которые уже есть в истории: `feat`, `fix`, `test`, `ci`, `chore`, `docs`, `refactor`.

```
feat(docker): образ, compose с именованным volume
test: матрица прав доступа и тесты /health
ci: пины actions по commit SHA
docs: запуск через docker compose
```

- описание в императиве, без точки в конце;
- область в скобках — если коммит про одну подсистему (`docker`, `ci`, `db`);
- тело — **зачем** правка, а не пересказ диффа;
- один коммит — одна мысль: «правка доступа + тесты к ней» нормально, «Docker + рефакторинг команд» — нет.

### Перед коммитом

```bash
git config core.hooksPath .githooks   # один раз на клон
```

Включает `pre-commit`, который запускает `ruff` и `pytest`; упавшие проверки
блокируют коммит. Осознанный обход — `git commit --no-verify` (например, для
правок только в документации, если CI всё равно догонит).

### Откат изменений

| Что нужно | Команда |
|---|---|
| отменить коммит, сохранив историю | `git revert <sha>` |
| вернуть всё к состоянию коммита | `git reset --hard <sha>` |
| вернуть один файл из коммита | `git checkout <sha> -- path/to/file` |
| убрать файл из индекса, оставив на диске | `git restore --staged path` |
| посмотреть, что было в коммите | `git show <sha>` |

`revert` безопасен и для уже отправленного: он создаёт новый коммит.
`reset --hard` переписывает историю — только для локальных коммитов, которые
никуда не уходили (сейчас remote не настроен, так что всё локальное).
Перед переписыванием истории удобно проверить себя через `git log --oneline`.

### Почему JSON с данными игроков не версионируются

`links.json`, `players_db.json`, `moderators.json`, `users_db.json`,
`votes.json`, `seen.json` содержат SteamID и Discord ID живых людей. В git они
не попадают:

- в `.gitignore` эти строки перечислены, но **закомментированы** — раскомментировать
  можно только если данные вынесены в приватный репозиторий;
- в рабочем клоне они дополнительно исключены локально через `.git/info/exclude`,
  поэтому `git status` остаётся чистым, а данные не утекают;
- `.dockerignore` не пускает их в образ.

Рабочее хранилище — SQLite (`quantum.db`) в `DATA_DIR`, для контейнера это
именованный volume `quantum-data`. Первичный перенос JSON в базу делает
`quantum/import_seed.py` из каталога `./seed` (подробности — в README).

Секреты (`DISCORD_TOKEN`, `CS2RED_*`, `STEAM_API_KEY`, `GITHUB_TOKEN`, ключи ИИ)
живут только в `.env`, который тоже в `.gitignore`.
